The first 30 days

Pick one use case. Prove the value. Productize from the pilot.

Start with a single repair, overhaul, or production flow — complex enough to show planning, resources, execution, and the twin together; narrow enough for fast results.

01Name the product owner, architecture owner, and pilot workshop.
02Lock the work-order workflow, role matrix, checklists, costing, and data owners.
03Define the canonical model, event catalogue, and API contract v0.1.
04Pick 20–50 assets; build the hierarchy and a 2D shop-floor map.
05Build the pilot as its own app — not on a demo stack.
06Set pilot KPIs: adoption, lead time, schedule adherence, data completeness.

From a real-data pilot to a decision-grade twin.

24-month roadmap. We build a reusable product core first — not a separate code branch for every customer.

M0 – M3

Foundation & pilot

  • Vertical slice: Request → Work order → Execution → QC → Acceptance.
  • ERPNext master and stock reference.
  • Twin 1.0 for one workshop, 20–50 assets.
M4 – M9

Product core

  • Workflow, checklists, certificates, mobile execution.
  • Costing and settlement, SSO, RBAC, audit.
  • ERP / HR / WMS adapters, 2D map, event timeline.
M10 – M15

Decision twin

  • Time-series telemetry and an event warehouse.
  • OEE, MTBF/MTTR, bottleneck and capacity simulation.
  • OPC UA, Modbus, MQTT gateway and vertical packages.
M16 – M24

Scale & automation

  • Multi-site, connector SDK, scenario versioning.
  • Human-approved recommendation workflow.
  • 3D twin when the action is clear and OT security is enterprise-ready.
